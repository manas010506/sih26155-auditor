# CIS Compliance Coverage Report

Last updated: 17 September 2026.

## Coverage Summary

The auditor evaluates Cisco IOS and Juniper JunOS configurations (which share one rule file) and
Terraform/AWS configurations. Configurations from other vendors are audited through the training
loop and are judged only on lines the tool actually read; otherwise they are reported as
"Partial" or "Not assessed" rather than scored.

**54 live rules** in total.

### Cisco IOS and JunOS (`engine/rules/cisco_rules.yaml`)

- **Live rules**: 36
  - **32 CIS rules**, citing the **CIS Cisco IOS 15 Benchmark v4.1.0**. 29 carry a benchmark
    recommendation number. 3 are standard hardening checks the benchmark does not number
    (HTTP server, HTTPS for web management, software version tracking) and are labelled
    "Not in CIS Cisco IOS 15 benchmark".
  - **4 NIST 800-53 rules**: AC-2, AC-3, AU-2, SC-8.
- **Parked rules**: 0
- **Closest-match mappings**: CIS-NET-019 (1.1.6) and CIS-NET-022 (1.5.9) check a narrower
  condition than the recommendation they cite.

### AWS (`engine/rules/aws_rules.yaml`)

- **Live rules**: 18, citing the **CIS AWS Foundations Benchmark v1.5.0**. 14 carry a
  benchmark recommendation number. 4 are standard hardening checks outside the benchmark
  (S3 versioning, S3 server access logging, RDS backup retention, RDS deletion protection) and
  are labelled as such.
- **Parked rules**: 2 (AWS-LOG-003, AWS-S3-001), kept in `engine/rules/backlog/` until the
  Terraform parser emits the attributes they check.
- **Removed**: 7 rules (CIS-CLOUD-019 to CIS-CLOUD-025) that duplicated existing checks and
  counted the same misconfiguration twice.
- **Closest-match mapping**: CIS-CLOUD-009 (1.16).

## Measurement Methodology

We measure two different things, deliberately, to give an honest assessment of the tool.

**1. Rule Correctness (Seeded Corpus)**

A corpus of 37 configurations generated by injecting known misconfigurations into a hardened
baseline. Because the injection is the ground truth, the labels are correct by construction.

- **Result**: 74 of 74 seeded misconfigurations detected.
- **False positives**: 18 across the corpus, 0 on the clean baseline. They are concentrated in
  absence-based checks, where a control present in a form the parser does not yet recognise
  reads as missing.
- **Purpose**: a regression check. It confirms every rule fires when its target
  misconfiguration is present; it is not an accuracy claim.
- **Reproduce**: `python -m tests.metrics`

**2. Real-World Detection (Held-Out Set)**

Six real-world Cisco IOS configurations from vendor documentation and public repositories,
never used while writing rules. Five contain hand-labelled issues; the sixth is a hardened
baseline. Each label records the rule that should catch the issue and the configuration line
where it occurs, and the labels were committed before the scoring script was run.
`tests/test_holdout_labels.py` checks that every label names a real rule and a valid line.

- **Holdout configs**: 6 (5 with labelled issues)
- **Issues labelled by hand**: 31
- **Issues detected**: 27, all at the labelled line
- **Detection rate**: **87.1%**
- **Reproduce**: run `.\reset_demo.ps1`, then `python -m tests.holdout_metrics`

### Misses

| Config | Issue | Reason |
|---|---|---|
| real_002.cfg | No exec-timeout on VTY lines | IOS applies a 10-minute idle timeout by default, which the engine treats as compliant |
| real_004.cfg | No exec-timeout on VTY lines | Same as above |
| real_006.cfg | RSA modulus 1024 < 2048 | No rule implements this check yet |
| real_006.cfg | `ip proxy-arp` enabled on interfaces | No rule implements this check yet |

### Findings Beyond the Labels

- **Hardened baseline (real_001.cfg)**: 2 findings, both correct under the rules:
  CIS-NET-022 (an SNMP v2c community at line 71) and CIS-NET-034 (a privilege-15 local user at
  line 24).
- **Labelled configs**: the other 80 rule hits have not been manually reviewed, so no
  false-positive rate is claimed for them.

### Change Note

An earlier version of this report gave a detection rate of 77.4% and zero false positives.
The 77.4% came from a scoring script that mapped labels to the wrong rules, and the
false-positive figure had not actually been measured. Both are withdrawn. The labels were
corrected against the configuration files and committed before the rewritten script produced
the figures above.

## Known Gaps

- No rules yet for RSA key size or proxy-ARP. They are not being added before submission,
  because they are exactly the held-out misses and adding them now would tune the rules to the
  test set.
- CIS AWS Foundations v1.5.0 has been superseded by v5.0.0; moving to it is a relabelling of
  existing rules.
- DISA STIG and ISO/IEC 27001 are supported by the architecture but not implemented.
